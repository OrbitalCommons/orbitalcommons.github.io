The data behind the discovery.

Star catalogs, planetary maps, and ephemeris kernels can be large and expensive to fetch. starfield-datastore gives those artifacts a common identity, validates their content, and resolves requests through a predictable cache chain.

01

Local first

Reuse an artifact from a content-addressed local store before reaching for the network.

02

Validate on access

Rehash and validate cached content. Corruption is reported; repair is explicit.

03

Explicit upstream

Use a configured mirror by default. Direct archive access is a deliberate opt-in.

From an idea to a few lines of code

Rust · describe and resolve an artifact
use starfield_datastore::{
    Artifact, ArtifactKey, ContentCheck, Datastore, Source,
};

fn main() -> starfield_datastore::Result<()> {
    let artifact = Artifact::new(
        ArtifactKey::new("archive/example.bin")?,
        vec![Source::new("https://archive.example/example.bin")],
    ).with_check(ContentCheck::default_binary());

    let store = Datastore::from_env()?;
    let path = store.get(&artifact)?;
    println!("{}", path.display());
    Ok(())
}

The example archive URL is a placeholder. Replace it with your artifact’s real source and configure a mirror or explicitly permit upstream downloads. Add a known digest and artifact-specific checks for stronger validation.

Choose what you need

SettingBehavior
STARFIELD_CACHE_DIROverride the local cache directory.
STARFIELD_MIRRORSet the ephemeris server base URL.
STARFIELD_ALLOW_UPSTREAM=1Permit direct archive downloads.
STARFIELD_OFFLINE=1Use local files only.

The default library features are mirror-http and progress. S3 and server dependencies are opt-in. Returned paths stay valid until an explicit remove or garbage-collection operation; fetches do not evict another consumer’s files.
